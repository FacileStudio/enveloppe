# enveloppe

Canonical event envelope for the Facile Suite. Defines the shared type contract (events, domain objects, actions) used by all apps communicating through Nook.

## Tech Stack

- **TypeScript** (types-only library) -- compiled with `tsc`, packaged via bun, targets ES2020 with NodeNext module resolution
- **Go** (types-only package) -- Go 1.24, pure struct/const definitions with JSON tags, no dependencies
- No runtime logic in either implementation. This is a pure schema/contract library.

## Project Structure

```
enveloppe/
  go/
    enveloppe.go      # Go types: Event[T], App, Action, ObjectType, domain structs
    go.mod             # module github.com/FacileStudio/enveloppe/go
  ts/
    src/index.ts       # TypeScript types: FacileEvent<T>, FacileApp, FacileAction, domain interfaces
    dist/              # Compiled output (committed, generated by tsc)
    package.json       # @facile/enveloppe v0.1.0
    tsconfig.json
    bun.lock
```

```bash
# TypeScript
bun add github:FacileStudio/enveloppe#ts

# Go
go get github.com/FacileStudio/enveloppe/go
```

## Domain Model

Six Facile apps: `sablier`, `opus`, `charles`, `plume`, `glouton`, `vision`

Three actions: `created`, `updated`, `deleted`

Six object types: `project`, `task`, `user`, `time_entry`, `invoice`, `document`

The `FacileEvent<T>` / `Event[T]` generic envelope wraps any domain object with metadata: app, object type, action, facile_id, payload, timestamp, and idempotency_key.

## Conventions

- Every domain object has a `facile_id` field as its cross-app identifier.
- Nullable fields use `string | null` in TypeScript, `*string` in Go.
- The `ts/dist/` directory is committed to the repo so consumers can install directly from GitHub without a build step.
- Both implementations must stay in sync -- same field names, same JSON serialization keys.
- No runtime code, no validation logic. This repo is the contract, not the implementation.
